# 海狸机实验室

目标：研究空白纸带上图灵机的停机行为，保存可复现的实验与证据，并观察状态、读写头和纸带随时间的变化。

新增 agent 终端接口：`./bb-lab.ps1 capabilities` 查看能力，`./bb-lab.ps1 run tm5_three_symbols --max-steps 1000` 无需 GUI 直接实验。命令统一输出 JSON 与退出码；支持配置导入、批量实验、状态查询、服务端控制、证据验证、精确回放和无图形环境的 SVG 导出。详见 [终端接口说明](agent-cli.md)、[agent 项目提示词](../AGENT_PROMPT.md)；自动读取项目指令的 agent 可从仓库根目录的 `AGENTS.md` 开始。

当前已完成可运行的第一版：独立机器配置、单机与四个基准的批量实验、单步/连续运行/暂停、检查点恢复、三类结论、独立证据验证、纸带动画、精确回放、时空图和图片导出。

已更新为多符号版本：GUI 全部使用英文；支持 2–32 个不同的整数符号（编号 0–255，空白固定为 0）。旧的二符号配置、结果和检查点继续兼容。新增 `tm5_three_symbols`（5 状态、3 符号、5 步停机）与 `three_symbol_cycle`（3 符号、4 步完整配置循环）作为可视化和验证基准。

在仓库根目录的 PowerShell 中启动：

```powershell
./start-lab.ps1
```

然后打开 **http://127.0.0.1:8765**。也可以直接启动：

```powershell
& '.\.conda\env\python.exe' -m uvicorn server.app:app --host 127.0.0.1 --port 8765
```

默认机器为二状态冠军，勾选 “Start paused for single-step observation” 后点 “Create experiment”；点 “Single step” 观察转移，或 “Run / resume” 得到最终结论。它在本仓库规则下执行 6 步，留下 4 个 1。回放使用独立控制按钮，不会修改实验状态。

不打开页面也能运行实验：

```powershell
& '.\.conda\env\python.exe' -m experiments.cli bb2_champion --max-steps 10000
```

每次运行均保存到 `results/<机器ID>/<运行ID>/`。PNG 导出同时保存到该运行的 `visualizations/` 并提供浏览器下载。退出服务时，未结束的实验保存为中断状态；重启后从右侧档案选择，点“连续运行”或“单步执行”恢复。

当前观察界面使用原生 JavaScript + Canvas，无需前端构建或外部 CDN；React/TypeScript 是后续复杂界面的迁移选择。后台目前用线程管理最多四个实验，方便交互与小规模批量操作；CPU 多进程、高速 Rust 内核、更强判定器和 GPU 实验仍是后续阶段。

## 1. 第一版研究范围

- 确定性、单纸带、双向无限纸带，有限符号集合，空白为 0；旧二符号模式使用 0/1。
- 工作状态为 A、B、C……，另设停机状态 H；工作状态数量不包含 H。
- 初始状态 A，读写头位于坐标 0，纸带全为 0。
- 一步依次执行：读取、写入、移动一格（L/R）、切换状态。进入 H 的转移也计一步，并执行它的写入和移动。
- 区分 S(n)：停机机器的最大步数，与 Σ(n)：停机时纸带上 1 的最大数量。界面和数据始终明确指标。
- 外部机器导入时记录来源与原始编码，对 Z/H、停机动作、未定义转移等约定显式转换，避免静默改变语义。

实验室不能提供适用于任意机器的通用停机算法。它提供模拟、对特定行为有效的判定方法，以及证明与未决案例管理。

## 2. 最少需要的六部分

| 部分 | 最少功能 | 产物 |

| 判定器 | 直接发现停机；完整配置重复的循环证明；其余保留未决 | 结论、证据、判定器版本 |

## 3. 结论与记录

机器结论只有三类：`HALTED`（已停机）、`NON_HALTING`（有有效证据证明不停机）、`UNKNOWN`（未决）。任务另外记录运行中、暂停、预算耗尽、取消、错误等执行状态。预算耗尽不等于不停机。

每次运行记录：机器 ID、语义版本、初始配置、实验参数、步数/时间/内存预算、代码版本、判定器版本、实际完成步数、结论与原因、证据位置、检查点和回放信息。使用随机搜索时另外记录种子与算法版本。

循环检测必须比较完整配置：工作状态、绝对读写头位置、全部非零纸带内容。哈希只用于索引，匹配后核对原始配置；可视窗口相似不能当作证明。允许证据检查失败，并将对应结论退回未决。

平移循环、漂移、宏步、归纳规则等后续扩展必须分别定义适用条件和验证方式，不能只凭图形重复推出不停机。

## 4. 推荐实现方式

- **Python**：第一版参考模拟器、实验编排、判定器原型；先把语义和数据格式固定。
- **TypeScript + React + Canvas 2D**：浏览器操作界面、纸带动画和时空图。Canvas 绘制大量格子，React 负责控制面板。
- **FastAPI**：本地实验服务，提供运行控制、快照和回放；通过 WebSocket 推送合并后的进度更新。
- **独立 JSON + 文件目录**：每台机器一个配置文件，每次运行一个结果文件夹。SQLite 后续只用于可重建的检索索引，原始配置与结果文件是保存依据。
- **Rust（第二阶段）**：当基准测试表明模拟是瓶颈，再加入高速内核和 CPU 并行批量运行；保留 Python 参考实现核对结果。使用同一套机器与轨迹格式，不必一次维护两套高速实现。

纸带先用非零格子的稀疏表示；性能阶段根据实际访问模式比较分块存储。累计步数、坐标与计数不得静默溢出；支持任意精度或显式停止并报告范围限制。传给浏览器的大整数使用十进制字符串，避免 JavaScript Number 精度丢失。

建议后续目录：

```text
core/           参考模拟器、机器语义、轨迹格式
deciders/       判定器和独立证据检查
experiments/    队列、实验配置、批量工具
server/         本地 API 与进度推送
web/            交互界面
fixtures/       有来源的小型基准机器
machines/       每台机器一个独立 JSON 配置文件
results/        按机器、运行分别保存的实验结果
tests/          语义、回放、证据验证与交叉检查
docs/           研究笔记、规则和结果说明
data/           可重建的本地索引；大文件不入 Git
native/         性能阶段再加入的 Rust 内核
```

## 5. GPU 决策

第一版不需要 GPU，优先 CPU 多核，并行处理不同机器。

单台机器的下一步依赖上一步，难以直接并行；不同机器的控制分支、纸带位置和停机时间差异较大，GPU 容易遇到分支分歧及不规则内存访问。渲染使用 GPU 与计算使用 GPU 是两个独立决策。

后续可以试验 GPU 批量预筛：大量短程机器、相近步数预算、明确的有限工作窗口。触及窗口边界或资源上限的任务交回 CPU 并标记未决，不能据此推断无限纸带上的行为。

启用 GPU 的门槛：同一批机器、同一语义、同一预算下，与优化后的多核 CPU 比较端到端吞吐、传输开销、内存和结果一致性。只有测得实际收益才引入；不承诺预设加速倍数。

## 6. 运动可视化

页面布局：左侧机器转移表与实验列表，中间纸带和时空图，右侧当前状态、统计与判定证据，底部回放时间轴。

### 纸带动画

- 显示每格 0/1、绝对坐标和读写头；读写头标注当前状态。
- 高亮本步读取格、写入变化、移动方向和使用的转移规则。
- 支持单步、播放、暂停、速度调整、跟随读写头/固定坐标、缩放和跳转指定步。
- 停机时明确显示 H；证据判定不停机与预算耗尽使用不同提示。

### 时空图

- 横轴为纸带绝对坐标，纵轴为真实执行步数；格子颜色表示符号，叠加读写头轨迹和状态颜色。
- 低速时逐步展示；长实验采用分块、采样和分辨率层级，明确显示采样间隔、坐标范围及省略区间。
- 平移和缩放后可以查看局部细节；点击图上的时间定位回放。
- 图形用于发现规律，证明仍需判定器与证据验证。

### 回放存储

- 小实验记录逐步增量，大实验保存周期检查点以及选定区间的增量。
- 精确跳转从最近检查点确定性重算；缺少检查点或区间过长时提示计算成本，提供取消。
- 必须明确哪些区间支持精确回放、哪些只保留统计或采样画面；不生成虚构中间帧。
- 宏步模式如果跳过原始转移，界面显示“宏步”和对应真实步数范围，不能把宏步当成单步播放。
- 运行进度与展示刷新解耦：计算可以高速执行，界面按固定刷新率读取快照，避免逐步推送拖慢实验。

## 7. 实施顺序与验收

1. **单机观察台**：机器编辑、参考模拟、纸带动画、时空图和保存加载。验收：单步与批量运行结果一致，暂停后可恢复，回放准确还原配置。
2. **可信实验台**：三类结论、循环证据、独立验证、独立文件记录、检查点恢复。验收：超时保持未决；伪造或损坏证据被拒绝；恢复运行与连续运行一致。
3. **批量研究台**：CPU 多进程队列、机器集导入、按结论与指标筛选、性能基准，按实测加入 Rust。验收：结果可复现，抽样与参考模拟器逐步核对。
4. **研究扩展**：安全的对称性规约与枚举覆盖审计、更多判定器、宏步分析、形式化证明对接；GPU 单独做基准实验。

初始基准包含：一步停机、完整配置循环、长时间未决、读写头持续漂移、左右镜像、负坐标访问，以及已知小状态冠军。全空间结论需要额外证明枚举覆盖、规约正确及所有机器分类完整；抽样或只跑冠军不能证明 S(n)。

## 8. 研究参考

- [BB(5) 证明论文](https://arxiv.org/abs/2509.12337)：S(5) = 47,176,870，使用 Coq 形式化验证。适合作为较长轨迹的复现实验，而非重新寻找未知数值。
- [bbchallenge 证明公告](https://discuss.bbchallenge.org/t/july-2nd-2024-we-have-proved-bb-5-47-176-870/237)：通过枚举、规约和专门判定器处理机器空间。
- [Turing machines deciders, part I](https://arxiv.org/abs/2504.20563)：判定器研究参考。
- [The Busy Beaver Frontier](https://scottaaronson.com/bb.pdf)：可计算性边界和研究背景。

第一阶段重点是可靠复现小机器与观察行为；之后再选择更大状态机器或未决案例作为研究目标。

## 9. Conda 环境与文件保存约定

使用仓库内的 Conda 环境 `.conda/env`，依赖声明见 `environment.yml`。包含 Python 3.12、pip、FastAPI 与 Uvicorn。以下命令在仓库根目录的 PowerShell 中执行：

```powershell
$env:CONDA_PKGS_DIRS = Join-Path $PWD '.conda/pkgs'
conda env create --prefix ./.conda/env --file environment.yml
conda activate ./.conda/env
python --version
```

更新依赖时使用 `conda env update --prefix ./.conda/env --file environment.yml`。环境和包缓存不提交到 Git。

`pip-freeze.txt` 保存当前 Python 包准确版本；在 Conda 基础环境创建后，可通过 `& '.\.conda\env\python.exe' -m pip install -r pip-freeze.txt` 复现 Python 依赖。

当前 Windows 机器已实际创建环境并验证 Python 3.12.15 和 pip 可用。`conda-win-64.lock.txt` 保存此次安装的准确 Conda 包版本与构建；仅适用于 win-64，其他平台使用 `environment.yml` 重新求解依赖。

当前 Conda 24.11.3 的 `conda run` 在本仓库含括号的路径中启动失败，默认 PowerShell 激活也出现兼容问题。已验证以下激活方式可用（此处 Conda 安装路径对应当前机器）：

```powershell
$activationScript = & 'D:\Anaconda3\Scripts\conda.exe' shell.powershell activate (Join-Path $PWD '.conda/env')
if ($LASTEXITCODE -ne 0) { throw 'Conda activation failed' }
$activationScript | Out-String | Invoke-Expression
python --version
```

也可直接使用环境里的 Python，无需激活：

```powershell
& '.\.conda\env\python.exe' --version
& '.\.conda\env\python.exe' -m pip --version
```

机器配置存放在 `machines/<machine_id>.json`。每个文件包含语义版本、状态、符号、初始配置和完整转移表。初始纸带用 `nonzero_cells` 保存非零格坐标，空列表代表全空白纸带；转移表的读取符号使用 JSON 字符串键 `"0"` 和 `"1"`。机器 ID 与文件名一致，仅使用字母、数字、下划线和连字符；改变转移表时新建机器 ID，名称或说明的修改不影响机器行为。

已提供四个基准配置：`halt_immediately.json`（一步停机）、`two_step_cycle.json`（两步完整配置循环）、`right_drifter.json`（基础判定器下预算耗尽、未决）、`bb2_champion.json`（6 步、4 个 1）。支持通过页面编辑 JSON，以新 ID 保存独立配置。

执行器在运行时创建以下结果目录：

```text
results/
  <machine_id>/
    <UTC时间戳>_<随机运行ID>/
      machine.json       本次实际使用的机器配置副本
      run.json           预算、配置摘要、代码与环境版本、开始结束时间
      environment.yml    本次依赖声明副本
      conda-explicit.txt 本次 Conda 包的准确构建清单
      pip-freeze.txt     本次 pip 包版本清单（如有）
      result.json        结论、结束原因、步数、1 的数量、最终状态
      snapshot.json      最近一次持久化的完整配置
      source/            本次实验的内核、判定器、服务与界面源码副本
      checkpoints/       恢复与精确回放所需快照
      traces/            分块轨迹与采样信息
      evidence/          判定证据与验证记录
      visualizations/    导出的时空图、图片等
      logs/              运行日志
```

运行 ID 使用不含冒号的 UTC 时间戳加随机标识，兼容 Windows 文件名；界面显示本地时间。同一机器重复实验创建新的运行目录，禁止覆盖旧结果。配置摘要基于规范化后的语义内容计算，用于识别同一行为定义；每次保存原始配置副本，保证日后修改源文件仍能复现旧实验。

结果目录及环境均在 `.gitignore` 中排除。运行中的结果通过临时文件写入后替换，避免中断留下半个 JSON；恢复同一次运行可以更新其任务状态，但必须保留恢复事件和检查点。

## 10. 第一版的运行边界与验证

- 运行预算：总步数（最多一亿）、活跃计算时间（最多一小时）、非零纸带格数量（最多十万）。暂停期间不计计算时间。纸带格预算是资源代理指标，不是操作系统级内存上限。
- 精确循环检测最多缓存两万个完整配置，累计纸带格条目最多二十万。达到上限时关闭该次运行的循环检测并记录事件，继续模拟；不会把缓存耗尽当作不停机证明。
- 判定不停机前，用独立实现从初始配置重放循环证据。独立验证最多重放一百万步；超过验证预算保持未验证，不伪称验证通过。
- 默认约保存一千个按真实步数采样的轨迹帧，另外保存初始、暂停、手工单步和终止帧。图中未采样区间不补造配置；时间轴精确回放从最近检查点重算。
- 目前轨迹保存在一个追加写入的 JSONL 文件中；API 最多返回约一千二百个样本，并明确标注二次抽样倍率。超长实验的分块压缩和索引仍待扩展。
- 运行过程中每约四分之一秒刷新持久化快照；强制结束进程后只能恢复到最近已保存配置。正常退出会保存检查点。
- 初始纸带允许非空，适合行为实验；海狸数比较应只使用空白纸带、A 状态、坐标 0 的标准初始配置。
- 当前结果是具体机器的行为结论；没有实现全空间枚举覆盖证明，不能把批量基准结果当作新的海狸数证明。

运行核心与持久化验证：

```powershell
& '.\.conda\env\python.exe' -m unittest discover -s tests -v
```

`tests/browser_smoke.cjs` 用于真实浏览器操作验证。当前机器的测试工具位于被忽略的 `.conda/browser-tools/`，使用本地 Chrome。服务启动后执行 `node tests/browser_smoke.cjs`；它会创建独立实验记录，并检查单步、连续运行、回放、证据验证、下载、基准结论和移动端布局。复现该检查需安装工具：`npm.cmd install --prefix .conda/browser-tools --cache .conda/npm-cache --no-audit --no-fund playwright-core`。观察界面本身不依赖该工具。

## 11. 多符号配置与结果格式

多符号机器使用 `schema_version: 2` 与 `semantics: "multi-symbol-two-way-write-move-halt-v1"`。`symbols` 是可配置的整数数组，例如 `[0, 1, 2]`、`[0, 1, 2, 3]` 或 `[0, 3, 7, 9]`；每个工作状态必须为每个声明的符号定义转移。写入值必须属于该集合，写入 0 会清空当前格。

初始纸带改用明确包含符号值的稀疏配置：

```json
"initial": {
  "state": "A",
  "head": 0,
  "cells": [
    {"position": "-2", "symbol": 2},
    {"position": "3", "symbol": 1}
  ]
}
```

`cells: []` 表示全空白纸带。只保存非空白格；坐标不能重复。v2 不允许同时指定旧的 `initial.nonzero_cells`，避免符号值存在歧义。v1 二符号配置无需转换，机器行为摘要保持兼容，旧证据仍可验证。

GUI 的 “Edit / import configuration” 面板中可指定状态数与符号数组，点 “Create multi-symbol template” 生成完整转移表模板；编辑 ID 与规则后点 “Save new machine”。模板默认立即停机规则，需按实验目标修改。内核支持最多 32 个工作状态；模板自动避开保留的 H 状态。

快照中的 `cells` 保存 `{position, symbol}` 列表，`nonblank_count` 是全部非空格数量，`symbol_counts` 保存每个非空白符号的数量，`ones` 仍仅表示符号 1 的数量。空白纸带无限长，因此不报告空白 0 的总数量。GUI 主指标使用非空格数量，另显示各符号计数。多符号结果不要把 `ones` 或 `nonblank_count` 自动解释为未经定义的海狸竞赛得分。

纸带和时空图按符号分别着色，图例随机器符号集合更新；读写头使用橙色边框，保留格子的符号颜色。循环判定、证据检查与回放都包含实际符号值，不能只按占用格的位置判断配置相同。
